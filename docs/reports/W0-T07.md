# W0-T07 — New, Open, Export, document tabs

Branch `task/W0-T07-documents`, off `task/W0-T06-compositor`.

## What was built

| File | What it is |
| --- | --- |
| `src/engine/documents.ts` | The open documents: `create` (File ▸ New), `open` (one document per file), `activate`, `command` / `undo` / `redo` through the core's commands and history, `close` with "save changes?", `closeAll` (one prompt at a time; Cancel stops), `export`, `thumbnails`. Sends `document_opened`, `document_changed` (name, size, dirty `*`), `active_document`, `layers`, `history`, `view`, `document_closed`, `close_dirty_document`, `progress`. |
| `src/engine/engine.ts` | Routes the messages and actions to `Documents` (`doc:new`, `export:as`, `tab:close`, `tab:close-all`, `hist:undo`, `hist:redo`, the `zoom:*` of the active document; Print Size now uses the document's ppi). |
| `src/engine/worker.ts` | Decodes files with `createImageBitmap(file, { imageOrientation: "from-image" })` into a canvas surface. |
| `src/engine/viewport.ts` | `ExportTarget`: a document-sized target the **same compositor** draws into at 100 % (no grid; a matte for JPEG), then `convertToBlob`. |
| `src/engine/protocol.ts` | `open_files` (UI → engine, `File[]`), `save_file` (engine → UI, a `Blob` and the request it answers); `LayerInfo.fill`, which the Layers panel reads (it showed "NaN" without it). |
| `src/io/open.ts` | What opens (PNG, JPEG, WebP, GIF first frame, BMP), the resolution in a PNG `pHYs` chunk or a JPEG JFIF header, and the document: one layer, **"Background"** when the image is opaque, **"Layer 0"** when it has transparency (Photoshop's names). No DOM, no worker globals. |
| `src/io/export.ts` | Format → MIME type, quality 0–100 → 0–1, JPEG matte, file name. |
| `src/core/surface.ts`, `src/core/raster/canvas-surface.ts` | `isOpaque(surface)` (band by band through `read`), `thumbnailOf(...)` (the layer drawn small in the document's frame). |
| `ui/js/native/documents.js` | File ▸ New: Fotox's dialog made live (presets fill the size, **Resolution** field added, units → pixels, Background Contents, name "Untitled-N"), with the **Clipboard** preset; File ▸ Open: `showOpenFilePicker` or a file input; **drop** on the window; Export: `showSaveFilePicker` first (it needs the click), then write the engine's `Blob`, or download. |
| `ui/js/actions.js`, `ui/js/main.js` | `dlg:new-doc`, `dlg:open`, `dlg:export-as` and the quick exports go to the functions above in engine mode; the tab bar's "+" goes through `runAction` so it opens the live dialog. |
| `ui/js/canvas.js`, `src/engine/test-pattern.ts` | The `?pattern` stand-in is removed, as W0-T04 promised. |

### The Layers panel against the engine

Found while writing this report, and fixed in the card: Fotox's panel sends
`add_layer` with `name: null` and `layer: "pixel"`, which the core refused, so
its **New Layer** button did nothing. Now, in headless Chromium:

- New Layer (twice): "Layer 1", "Layer 2" above the active layer, each active,
  History "New Layer" × 2.
- Opacity field 40 + Enter: the layer at 40 %, **one** "Opacity Change" (the
  panel sends the value twice — Enter, then `change` on blur — and a command
  that changes nothing is no longer recorded, as in Photoshop).
- Double-click the name, type "Sky": renamed.
- What W1 brings answers "not implemented yet" (a toast, not an error): the
  group button, Delete (`delete_layers`), the Fill field, and **clicking a
  row** (`select_layers`, W1-T01) — so in W0 a row click does not change the
  active layer; New Layer does.

## What changed from the card

- **Save in "save changes?"**: there is nothing to save to before the project
  file (W1-T07), so Save keeps the document open and toasts "Saving arrives
  with the project file (W1-T07). Export the image, or close without saving."
  rather than pretending.
- **Opened layer name**: "Background" for opaque images, "Layer 0" when the
  image has transparency — Photoshop's naming, which the card cites; the card
  says "a Background layer" for every file.
- **The Clipboard preset** is read at once only when the page already has the
  permission; otherwise it says "click to read" and reads on click, because
  `navigator.clipboard.read()` waits on Chrome's permission prompt and the New
  dialog must not wait for it (the first version did, and never opened in the
  headless browser).
- **Export dialog**: Fotox's Export As had PNG / JPG / TIFF and CMYK / bit-depth
  options the engine does not have; it now offers PNG, JPG, WebP and the
  quality. "Export as ▸ PNG… / JPG… / WebP…" preselect their format.
- "Save As ▸ PNG / JPG / WebP" export at once at quality 90 (Photoshop's
  Quick Export); the other formats in those submenus still toast "not
  implemented yet".
- `LayerInfo.fill` was missing from W0-T03's protocol types.
- A document is "dirty" when its history is not at the saved state, so undoing
  every edit makes it clean again (see VERIFY).

## VERIFY

- The opened layer's name ("Background" / "Layer 0") and the new transparent
  document's ("Layer 1").
- Resolution: PNG `pHYs` and JPEG JFIF are read; a JPEG's EXIF resolution is
  not (Photoshop reads it); 72 ppi otherwise.
- JPEG export flattens transparency onto white.
- Undoing back to the saved state clears the dirty `*`.
- After closing the active tab, the tab to its left becomes active.
- The largest document side accepted by New: 30 000 px (the browser's canvas
  limit may be lower; Photoshop's is 300 000).
- EXIF orientation is applied on open (`imageOrientation: "from-image"`).

## Not verified in the browser

- **The File System Access pickers** (`showOpenFilePicker`,
  `showSaveFilePicker`): headless Chromium cannot drive them, so the file-input
  and download fallbacks were tested instead. Rob, in Chrome/Edge: Ctrl+O shows
  the system picker with several files allowed; Export asks where to save and
  writes there.
- **A real drag and drop** from Explorer onto the window (only a synthetic
  drop event was tried).
- **The clipboard permission prompt** (the "click to read" path): only the
  already-granted path was tried.
- Real photos (EXIF orientation, colour profiles, GIF, BMP) — the test files
  were made by the browser's encoders.
- The exit criterion "a 4000 × 3000 photo opens in ≤ 1 s" measured on Rob's
  machine: headless took under 0.2 s for two files.
