## What was built

| File | What it is |
| --- | --- |
| `ui/index.html`, `ui/css/`, `ui/js/`, `ui/assets/icons.svg` | Fotox's interface, copied verbatim (37 files). The CEF paths (`bridge.js`'s `isNative`) are dormant because `window.sendNativeMessage` does not exist in a browser; the mock engine answers. |
| `ui/tools/check-data.mjs` | Fotox's interface data checker, now the third part of `npm run check` (`check:data`). |
| `vite.config.ts` | `root: "ui"`, and a small plugin that emits `ui/assets/` into `dist/assets/`: `ui/js/icons.js` fetches the sprite at runtime, so the bundler would otherwise not know it exists and a build would have blank icons. |
| `eslint.config.js` | JavaScript rules for the copied files (`js.configs.recommended`, browser + node globals, `no-unused-vars` off because the copy is verbatim). The Surface rule stays on `src/` only: the interface draws the engine's thumbnails into its own canvases and never holds a layer's pixels. |
| `package.json` | `check:data` and `check = typecheck && lint && check:data`. |

Added by this session:
- `ui/index.html`: an inline SVG favicon (the logo mark `main.js` draws). Without
  it the browser requests `/favicon.ico`, gets a 404 and logs an **error** in
  the console, which fails the card's first Check item.

## What was tried, and what was seen

**No Chrome or Edge on Windows here.** This is a Linux cloud session with a
headless Chromium (Playwright's build 1194). Everything below was seen through
that browser, driven by a script kept out of the repository.

On `npm run dev` (`http://localhost:5173/`):
- the page renders (menu bar, tool bar, options bar, dock, the demo document,
  status bar); the diagnostic overlay of `index.html` does not appear;
- **console**: before the fix, one `error` — the `/favicon.ico` 404; after it,
  nothing but Vite's `[debug]` lines and one Chromium `[verbose]` note ("Password
  field is not contained in a form", from the Account dialog). No errors, no
  warnings;
- **menus**: all nine top-level menus open (File 23 rows, Edit 27, Image 19,
  Layer 27, Select 19, Filter 17, View 23, Window 30, Other 16);
- **every menu command**: the 410 enabled leaves were run through
  `runAction` — no exception; the mock answers with its toasts;
- **dialogs**: all 140 definitions in `ui/js/data/dialogs.js` were opened
  with `openDialog(id)` and closed — no exception, each has its title bar;
- **panels**: the 15 dock tabs were clicked in turn — no exception;
- "Mock engine connected (browser mode)" toasts at start.

On `npm run build`, with `dist/` copied to a sub-folder
(`http://localhost:8088/some/sub/`): the page, the CSS, the JS chunk and
`assets/icons.svg` all load (200), the icons show, the menus open, the console
is empty. So `dist/` works from any path (D-002).

`npm run check` (typecheck, lint, `check-data.mjs`) is clean. `check-data.mjs`
reports one note, not a problem: two dialogs (`save-changes`, `layer-lock`)
are reachable only from disabled items — the engine opens them in Fotox.
