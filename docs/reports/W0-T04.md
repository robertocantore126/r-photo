# W0-T04 — The viewport

Branch `task/W0-T04-viewport`, off `task/W0-T03-worker`.

## What was built

| File | What it is |
| --- | --- |
| `ui/js/canvas.js` | In engine mode `#viewport` gets a `<canvas>`, transferred to the worker (`viewport_canvas`, with the size in device pixels, the ratio and the workspace's background colour). A `ResizeObserver` (device-pixel box) and a `matchMedia` watch on the ratio send `viewport_resized`. Pointer Events → `pointer` (pressure, tilt, button / buttons, pointer type, modifiers, time; a drag's coalesced samples one by one; `setPointerCapture` on down), wheel → `wheel` (deltas converted to device pixels). Space is tracked here (the engine sees no keys) and travels in `modifiers.space`. Cursor: grab for the Hand / Space, zoom-in for the Zoom tool. Fotox's `reportViewportBounds` (CEF's hole) is replaced. |
| `src/engine/view.ts` | `View`: zoom (device pixels per document pixel; 1 = Photoshop's 100 %), centre, viewport size. Zoom about a point, pan, Fit on Screen, Fill Screen, 100 %, Print Size, Zoom In / Out through Photoshop's presets, continuous wheel zoom, and a clamp that keeps the image in view. The document's origin is rounded to whole device pixels. No DOM, no worker. |
| `src/engine/viewport.ts` | Owns the transferred `OffscreenCanvas` (one of the two places the Surface rule allows). Draws only on the animation frame after `requestDraw()`, once however often it is asked. The rest of the engine draws through `ViewportTarget` (`clear`, `fillRect`); W0-T06 adds what the compositor needs. |
| `src/engine/navigation.ts` | Hand tool, Space (+ Ctrl: zoom in, + Alt: zoom out, Photoshop's temporary Zoom), middle button, Zoom tool click (Alt: out), wheel. |
| `src/engine/test-pattern.ts` | The card's "temporary pattern until W0-T07": a 4000 × 3000 stand-in (the exit criteria's size), coloured 250-pixel blocks with a 1-pixel grid every 50 pixels, drawn for the visible part only. Shown with **`?pattern`** in the URL (the interface sends `debug:test-pattern`). |
| `src/engine/engine.ts` | Tracks the tool (`tool:<id>` actions), handles `zoom:in/out/fit/fill/100/print` (their prefix is UI-local, which only means "no toast"), `set_zoom`, the viewport messages, pointer and wheel; sends `view` after every change so the rulers, the zoom field and the tab follow. |
| `src/engine/protocol.ts` | `viewport_canvas`, `viewport_resized`, `pointer`, `wheel` and `Modifiers`, as `ARCHITECTURE.md` §2 lists them; `viewport_bounds` (CEF's) removed. |
| `ui/js/actions.js` | Fill Screen / Print Size: the mock's stand-in `set_zoom` (200 % / 72 %) is no longer sent in engine mode, where it overrode the engine's answer. |
| `ui/css/app.css` | `#viewport` positioned and clipped, `touch-action: none` (pen and touch go to the engine), the cursors, `.viewport-canvas` filling it. |

### Photoshop's behaviour, as implemented

- Zoom presets (Ctrl + / −, Zoom tool): 0.78 … 66.67, 100, 200 … 800, 1200,
  1600, 2400, 3200 … 12 800 %.
- A document opens at the largest preset that shows it whole, ≤ 100 %.
  Fit on Screen (Ctrl+0) fits exactly, also above 100 %.
- Wheel: vertical scroll; Shift + wheel: horizontal; **Alt + wheel: zoom about
  the pointer** (Photoshop on Windows). **Ctrl + wheel also zooms**, because
  that is how Chrome delivers a trackpad pinch (Photoshop's Ctrl + wheel
  scrolls horizontally). A notch ≈ × 1.2, the same at every display scale.
- Panning cannot push the image's edge inside the viewport's; a small image
  stays centred (Photoshop without Overscroll).
- Resizing the viewport keeps the centre.

## What was tried, and what was seen

Headless Chromium (Linux) through Playwright, at device scale 1 and 1.5 (the
latter emulated), on `npm run dev` with `?pattern`:

| Check | Seen |
| --- | --- |
| Pattern opens | at 25 % (dpr 1; fit 27 %) and 33 % (dpr 1.5; fit 40 %): the largest preset that fits. |
| Ctrl + = | 25 → 33.33 %; status bar zoom field follows ("33%"). |
| Ctrl + 0 | 26.4 % at dpr 1, 39.6 % at dpr 1.5 (the fit), centred (2000, 1500). |
| Ctrl + wheel × 5 at a point | ×2.46; the document point under the pointer moved **≤ 2 document pixels** (rounding of the origin), at both scales. |
| Alt + wheel out | the point stays under the pointer (≤ 1 px). |
| Plain wheel 100 px | pans vertically by exactly 100 device px / zoom (dpr 1); at dpr 1.5 less, because the clamp stopped it at the image's edge. |
| Space + drag 120 × 60 CSS px | the centre moved by exactly −120·dpr/zoom, −60·dpr/zoom. |
| Middle-button drag | pans. |
| Zoom tool click / Alt-click | next preset in (67 %, 100 %) / out. |
| Ctrl + 1 | zoom 1. At dpr 1.5 the screenshot shows 1 image pixel per device pixel: the 250-pixel blocks are 250 screenshot pixels wide, the 1-pixel grid lines are sharp. |
| Resize the window (1400×900 → 1000×700) | the canvas follows; no blur in the screenshot. |
| Rulers (Ctrl+R) | follow the view: at 100 %, dpr 1.5, 100 document pixels span 100 device pixels on the ruler, matching the pattern. |
| No document (no `?pattern`) | the viewport is the workspace's grey. |
| Console | no error or warning, at either scale; the full smoke run (410 menu commands, 140 dialogs, 15 panels) still clean. |

The first run at dpr 1.5 found a bug: under emulated scaling
`devicePixelContentBoxSize` reports **CSS** pixels, so the engine believed the
viewport was two thirds of its real size (fit gave 26 % instead of 40 %). The
size is now CSS size × ratio, and the browser's exact figure is used only when
it agrees within a pixel.

`npm run check` and `npm run build` are clean.

## What changed from the card

- **Fotox's `view.rs` was not available** (see `NIGHT.md`); the view is written
  from Photoshop's behaviour, with the guesses marked `VERIFY` below.
- Rotate View is not here (W2-T11 in `COVERAGE.md`).
- Ctrl + wheel zooms (see above) — a deliberate difference from Photoshop, for
  trackpads.
- `navigation.ts` and `test-pattern.ts` are extra files: the card's list has
  `view.ts` and `viewport.ts` only. The first keeps input handling out of the
  view's arithmetic; the second is deleted by W0-T07.
- The document tab does not show the pattern's zoom: there is no tab without a
  document (W0-T07). The status bar's zoom field and the rulers do follow.
- `ui/js/canvas.js` and `ui/js/actions.js` stay JavaScript although this card
  touches them: the card names `canvas.js` as a `.js` file, and the rule in
  `AGENTS.md` ("a file moves to TypeScript when a card touches it") is read
  here as "when a card rewrites it". Flagged in `NIGHT.md`.

## VERIFY

- `ZOOM_STEPS` (view.ts): Photoshop's preset list, and 12 800 % as the maximum.
- `MIN_ZOOM` = 0.78 %: Photoshop goes lower on huge documents.
- Wheel zoom rate (× 1.2 a notch) and the wheel mapping (plain = scroll,
  Alt = zoom; the "Zoom with Scroll Wheel" preference).
- Opening zoom: the largest preset ≤ 100 % that fits.
- Fit on Screen: no margin, and above 100 % for small images.
- Fill Screen: covers the viewport.
- Print Size: 72 ppi screen and 72 ppi document until documents carry their
  resolution (W0-T07).
- The clamp (no Overscroll): how far Photoshop lets the image go.
- Zoom In / Out from the keyboard zoom about the viewport's centre.
