# W0-T03 — The engine worker and its transport

Branch `task/W0-T03-worker`, off `task/W0-T02-interface`.

## What was built

| File | What it is |
| --- | --- |
| `src/engine/protocol.ts` | Fotox's message names (`UI`, `ENGINE`) and, new, a TypeScript type for every message (`UiToEngine`, `EngineToUi` unions), the UI-local action prefixes (`UI_LOCAL_ACTION_PREFIXES`, `isUiLocalAction`) and the worker's reply envelope `EngineFrame { message, payload? }`. |
| `src/engine/engine.ts` | `Engine`: handles one message at a time and answers through a `post` function it is given. W0-T03's behaviour: `hello` → toast **"Engine connected"**; UI-local actions → silence; any other action or command → toast **"`<id>`: not implemented yet"**; tool options, colours and direct-input are kept; messages about a document are ignored (there are none). | `src/engine/worker.ts` | The worker entry: `self` → `Engine`. The only file that knows it is in a worker (`/// <reference lib="webworker" />`). |
| `ui/js/native/protocol.js` | Now one line: re-exports `UI`, `ENGINE`, `UI_LOCAL_ACTION_PREFIXES`, `isUiLocalAction` from `src/engine/protocol.ts`. Fotox's frame encoder/decoder is gone. |
| `ui/js/native/bridge.js` | Two transports: the worker (default) and the mock (`?mock`). `init()` starts `new Worker(new URL("../../../src/engine/worker.ts", import.meta.url), { type: "module" })`; `send(message, transfer)` posts; replies go through the same `receive`, so every `bridge.on` listener works unchanged. ### `isNative`

The interface checks `bridge.isNative` in about 40 places, and every one of them
means "the engine, not the interface, owns this" (the documents, the view, the
Layers and History panels, the image and filter dialogs). That is what the
worker is. So `isNative` keeps its name and is now `true` unless `?mock` is in
the URL; the doc comment on it says so. The alternative — renaming it
everywhere — would have touched ten JavaScript files that no card asks to
change, and `AGENTS.md` says a file that a card touches moves to TypeScript.

Consequence: without `?mock` the interface is in engine mode. The demo
document, its layers and its history are gone; the workspace is empty and the
panels say "Open a document…" until W0-T04 (the viewport) and W0-T07
(documents). With `?mock` everything is as in W0-T02.

## What was tried, and what was seen

Headless Chromium (Linux), not Chrome on Windows — see below.

On `npm run dev`:
- **"Engine connected"** toasts at start; the page's body has class `engine`;
  a module worker starts from `/@fs/…/src/engine/worker.ts?worker_file&type=module`.
- **Window ▸ Navigator** (a panel): no toast.
- **Layer ▸ Merge Visible**: toast "layer:merge-visible: not implemented yet".
- **File ▸ Save As…**: toast "doc:save-as: not implemented yet".
- All 410 enabled menu commands run through `runAction`, all 140 dialogs
  opened, all 15 dock tabs clicked: no exception, no console error or warning.
- **`?mock`**: body without `engine`, "Mock engine connected (browser mode)",
  the demo document, the mock's own toasts ("… not implemented (mock engine)").

On `npm run build`, `dist/` copied to a sub-folder: the worker is its own chunk
(`assets/worker-*.js`, 2.4 kB) and starts from the sub-path; the same four
checks give the same results, with and without `?mock`.

`npm run check` and `npm run build` are clean.

## What changed from the card

- The engine logic is in `engine.ts`, not in `worker.ts`: the card lists
  `worker.ts` as the entry; splitting keeps the worker's globals out of the
  code W12 will test.
- The message types were written from the interface's own use of each message,
  because **Fotox's `PROTOCOL.md` was not available** to this session (see
  `NIGHT.md`). Field meanings that are inferred are commented; the layer and
  status messages are typed only as far as the interface reads them.
- The new messages of `ARCHITECTURE.md` §2 (`viewport_canvas`,
  `viewport_resized`, `pointer`, `wheel`, `open_files`) are not here: they
  arrive with the cards that send them (W0-T04, W0-T07).
- `viewport_bounds` is still sent by `canvas.js` (Fotox's CEF hole); the engine
  ignores it. W0-T04 replaces it.
- The toast says "`<action id>`: not implemented yet" (the mock said
  "… (mock engine)"). Photoshop has no such message; W1-T09 removes the need.

## VERIFY

None: nothing here is Photoshop's behaviour.

## Not verified in the browser

- All of the above was seen in **headless Chromium on Linux**. Rob, in Chrome
  or Edge on Windows: the "Engine connected" toast; a menu item such as
  Layer ▸ Merge Visible toasts "not implemented yet"; Window ▸ Navigator toasts
  nothing; `?mock` shows the demo document again.
