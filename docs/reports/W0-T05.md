# W0-T05 — Core: Surface, Document, Layer, Command, History

Branch `task/W0-T05-core`, off `task/W0-T04-viewport`.

## What was built

| File | What it is |
| --- | --- |
| `src/core/surface.ts` | The `Surface` interface of `ARCHITECTURE.md` §3 (`read`, `write`, `draw`, `regions`, `snapshot`), `Rect`, `PixelBlock`, `SurfaceFormat` (`rgba8` straight alpha, `gray8`), `DrawOp` (W0: `fill`, `clear`), a `SurfaceFactory` the engine passes in, and rectangle helpers. No DOM. |
| `src/core/raster/canvas-surface.ts` | `CanvasSurface`: one `OffscreenCanvas` per surface; `gray8` kept as opaque gray RGBA. `regions()` yields one clipped rectangle. `snapshot()` shares the canvas and marks it shared; the next side to write copies it first. `fromImage(ImageBitmap)` for W0-T07, `drawableOf(surface)` for the viewport (W0-T06), `canvasSurfaces` as the factory. |
| `src/core/layer.ts` | Fotox's / Photoshop's layer model: `pixel`, `group`, `fill`, `adjustment` and (typed only) `shape` / `text` / `smart`; every layer has `visible`, `opacity`, `fill`, `blend` (the 27 modes + Pass Through, Fotox's ids), `clipped`, `locks`, `mask` (gray surface, enabled, linked, offset), `offset`. `background` marks Photoshop's Background layer. `snapshotLayer` copies a layer with copy-on-write surfaces. |
| `src/core/document.ts` | `Document { width, height, ppi, colorProfile, layers (bottom → top), activeLayer, selection, guides, channels, nextLayerId }`, `findLayer`, `layersTopDown` (the Layers panel's order), `countLayers`. |
| `src/core/command.ts` | The `Command` union — `add_layer`, `delete_layer`, `set_layer_props` (visible, opacity, name), `fill_layer` — as plain data with Fotox's names. `parseCommand` checks what arrives from the wire, `validate` checks it against the document, `apply(doc, command, { surfaces }) → { ok, effect } \| { ok: false, error }`. `Effect { label, pixelsChanged (layer + document rect), propsChanged, structureChanged }`. All or nothing: `validate` covers everything `apply` relies on. |
| `src/core/history.ts` | `History`: the opening state plus up to 50 states (Photoshop's default), each a snapshot of the layer tree with copy-on-write surfaces; `record`, `undo`, `redo`, `jumpTo`, the labels and the current index for the History panel; a new edit drops the undone states. |
| `THIRD_PARTY.md` | BitMappery's row says what was really taken (see below). |

### From BitMappery

The card names BitMappery's `document-factory`, `layer-factory` and types as
the starting point. Read on 26 Sep 2026 (raw files; its repository API was not
reachable), they turned out to hold `HTMLCanvasElement`s in a flat layer list
with BitMappery's own fields (`left`, `top`, `transparent`, `rel` …). The
model this card asks for is Fotox's (`ARCHITECTURE.md` §4). So only the
factories' **shape** was taken (`create` with every default spelled out, a
counter for ids), credited in `layer.ts` and `document.ts`; no file is
recognisably BitMappery's, so no MIT header was added. If Rob reads this as
"recognisably theirs", the header to add is the one at the top of BitMappery's
`src/model/types/layer.ts` ("Igor Zinken 2020-2026 - https://www.igorski.nl").

## What was tried, and what was seen

The card's check is typecheck and lint only (W0-T07 exercises the core from
the interface). `npm run check` is clean.

Beyond that, the modules were loaded in headless Chromium through the dev
server by a scratch script (not committed; D-003):

- A new `rgba8` surface reads `[0,0,0,0]`; after `fill` red, red.
- **Copy-on-write**: after `snapshot()` and a blue fill of half the live
  surface, the live one reads blue there and red elsewhere, the snapshot
  still reads red.
- `write` then `read` round-trips opaque pixels exactly; a read half outside
  returns zeros for the outside half; `regions({x:-5,y:3,w:8,h:100})` on a
  10 × 10 surface yields one rectangle `{0,3,3,7}`.
- `gray8`: new = 0, fill 200 → 200.
- Document 100 × 80 with a white Background: `add_layer` → "Layer 1" above it,
  active; `fill_layer` green → "Fill", dirty rect the whole layer;
  `set_layer_props` visible false → "Layer Visibility".
- Refused, document untouched: opacity 2 ("Opacity must be between 0 and
  100 %."), an unknown layer ("That layer does not exist."), an unknown op
  ("levitate: not implemented yet"), deleting the last layer ("A document must
  keep at least one layer.").
- History: undo → visible again; undo → the layer transparent again; redo →
  green; a new edit after an undo drops the redo state; jump to the first
  state and redo three times restores name and pixels; the Background is
  untouched throughout; **60 edits keep 50** states.

Chromium printed its "Multiple readback operations using getImageData are
faster with willReadFrequently" warning during the script's many single-pixel
reads. Normal use reads rarely (W0 never does); if the thumbnails of W1-T03
trigger it, the surfaces that are read often get `willReadFrequently`.

## What changed from the card

- `delete_layer` is singular, as the card writes it (W1-T01 has
  `delete_layers`).
- Colours in commands are 16-bit, as the protocol carries them (`set_colors`),
  and converted to 8-bit by the canvas surface.
- `parseCommand` is extra: commands arrive as JSON from the interface, so their
  shape is checked before `validate` looks at the document.
- The history keeps the **whole tree** as copy-on-write snapshots rather than
  only the changed surfaces: unchanged surfaces are shared between states, so
  the memory is the same and restoring is simpler. The card's intent ("the
  Surfaces a command changed plus the layer tree") holds for memory.
- The opening state's label is a parameter (Photoshop shows "Open" or "New");
  the History panel in `layers-panel.js` still writes "Open" itself (W1-T04).
- Merging repeated slider edits into one step is W1-T01.

## VERIFY

- History labels: "New Layer", "Delete Layer", "Layer Visibility", "Opacity
  Change", "Rename Layer", "Layer Properties" (several at once), "Fill".
  Photoshop records visibility only with History Options ▸ "Make Layer
  Visibility Changes Undoable"; R-photo always does (W0-T07's check needs it).
- Deleting the only layer is refused (Photoshop disables the command).
- After deleting the active layer, the one below becomes active (the one above
  when the bottom one went).
- The new layer's name: "Layer N" with N one more than the highest used.
